# Original model-step journal: isolated source proposal

This proposal extends only its isolated checkout and owned local fixtures. Production inference remains HOLD. There is no upstream sender, production original issuer, deployment, credential loader, reservation creator, model runtime or live migration in this slice. A successful logical journal claim never authorizes a physical send.

## Frozen design

Use task-scoped `effects.kind = model_step` children in the same FactoryControl SQLite file. This successor uses database schema 3 for an authenticated immutable parent manifest, all expected slots, each admitted child binding and one immutable claim witness per claimed child. The authenticated envelope remains version 2. Each nonempty fixed manifest authenticates exact request IDs, nonces, node/ordinal slots and call/body/model/recipient bindings. Unique constraints cover parent/slot, request ID and nonce. The manifest is already committed into the immutable task specification before the parent Flow intent. Empty or dynamically discovered call sets are unsupported pending a trusted finalized transcript.

A distinct pure envelope version 2 requires `taskType: software`, a `codex/` branch and a mandatory `originalInference` specification carrying ordinary class/version, issuer/factory/origin identity, complete-original digest and the manifest digest. A v1 task cannot inherit this class from a caller or adapter. Authentication means only that the host-configured verifier authenticated the bytes; the issuer's independent access to complete original context is still unimplemented and unqualified.

The host owns the bootstrap, receiver comparison and original control/spending handles out of band. A request supplies only an opaque capability and current lease, never a verifier, signer, classification upgrade, alternate database or new slot. Manifest enrollment and child registration serialize under the same `BEGIN IMMEDIATE` used for parent settlement. The parent must already be the exact running native `flow_call`; full task/spec/parent request, lease token hash/expiry, class, manifest, body, model, principal and recipients are compared.

Dedicated registration commits the immutable binding and accepted child. Dedicated logical claim commits one exact durable witness, accepted-to-running CAS and claim event in one control-database transaction. Duplicate/restarted/running/unknown/terminal claims return observation-only state only after validating the stored child/binding/witness. Fresh claims recheck original lease/OFF and the existing parent reservation under original control/spending locks. They create no reservation and make no network call. Receiver/body comparison must succeed through the configured host seam. Missing comparison refuses; a fixture comparison is not a qualified production renderer.

Dedicated settlement preserves unknown attempts and prohibits declaring a started child not applied. An accepted child cannot become unknown or succeeded without the dedicated claim. Running/unknown/succeeded observations, including idempotent success, require the exact saved witness; accepted/not-applied children must have none. Generic admit/start/settle/reconcile cannot operate on `model_step`. Successful parent settlement requires the exact authenticated manifest, every expected slot admitted and succeeded with its matching witness, and no unexpected children. A required not-applied child may be terminal but does not satisfy successful inference. A flagged task without a manifest cannot complete through a zero-child default. Finalization and registration share the original SQLite writer lock, so parent completion cannot race a later child insert.

Existing openTaskEffects and causal effects include task-scoped children: submission, release, takeover, cancellation, cell retirement, worker idle and status retain unresolved children. NativeCell recovery must distinguish children from parent Flow effects and report child reconciliation/HOLD without sending a child to the Flow observer. Parent native observation cannot settle success while its manifest is incomplete. These are controller-recorded lifecycle checks, not global worker quiescence.

Schema installation is explicit, paused and recorded-drained. The FactoryControl constructor does not migrate v1, create extension tables behind v1, or reset a schema3 database to v1. The prior schema2 prototype is refused before journal-mode writes; no witness is inferred from its states or events. Recorded-drained state does not prove old open v1 writers are quiescent; separate live migration qualification must account for every writer before any actual original upgrade. Exact v1 presentation/CLI/watch readers remain closed on schema3 pending a distinct compatibility review.

## Implemented source-only slice

The candidate uses literal task scope and `kind: model_step`; owner, task ID and epochs match the original parent. A branded v2 provenance capability creates an in-process manifest proof. `OriginalModelStepJournal.admitParent()` verifies the exact task/lease/native request and inserts the parent, manifest and all expected slots in the same transaction. Ordinary generic parent admission refuses flagged tasks. Slot commitment hashes exclude the parent/task/lease and cover independently knowable call, model, recipients and exact body projection, avoiding a circular task/manifest hash.

Each fixed slot authenticates `requiredOutcome: succeeded`. Durable enrollment independently keeps runtime and completion fenced if task metadata is missing or corrupted; an enrolled task's immutable identity/specification/digest cannot be updated through an old SQL writer connection. The SQL parent trigger checks exact expected membership, missing child joins, extra children, effect scope/task/owner/epochs/digests and success outcome. Explicit foreign-key checking remains connection-local; deliberate owned fixtures test rejection after bypassed FK corruption without claiming arbitrary SQL containment.

`abortNeverDispatched()` requires the exact authenticated enrollment capability and an accepted parent with no durable child claim. It atomically records an immutable whole-plan abort tombstone and closes the parent not applied. Duplicate abort observations revalidate the entire stored manifest, slots, bindings, child states and absence of claims, including after OFF or lease expiry. Missing expected slots receive no fabricated child result or envelope; the exact fixed plan's abort covers them as never dispatched in the recorded source-only lifecycle. It preserves every request ID, nonce and slot, releases no spending and cannot reset the parent lifetime identity. A running/unknown parent cannot use this path. This is not a provider-absence or global physical-quiescence proof.

`claim()` is a logical journal CAS only. Its seven-column claim row binds child/parent keys, complete envelope digest, receiver digest, canonical witness JSON/hash and admission time. The closed witness includes exact task/spec, original call/nonce/slot/principal/role/recipient, lease/token hash/expiry, original parent reservation/provider/ceiling, charged amount and zero-overcommit admission snapshot. A module-private per-controller window permits one exact insert and one exact start, then closes before the event callback. All configured receiver/clock calls, canonical bytes and SQL arguments are computed before that window. The exported general mutation helper and ordinary FactoryControl readers cannot open it. Generic events do not mint authority. SQL forbids accepted-to-unknown and terminal regressions independently of journal methods.

The host-configured spending handle checks the existing parent reservation; it cannot allocate another reservation or transfer a Fly reservation to Modal. There is no allocation of per-step/physical provider ceilings in this proposal. Only control-database witness/CAS/event are atomic. The enclosing paid transaction serializes a cooperating admission read; it is not a two-database atomic commit or physical billing proof. If the paid transaction's acknowledgement fails after the control commit, the durable claim may remain despite a thrown call; retry observes the same exact witness without re-admission or a second claim event. Post-claim reconciliation uses the stored admission snapshot after restart/OFF/expiry, without demanding a live lease or a fresh charge snapshot. A successful claim does not establish affordable physical inference. `settle()` records a source-only host observation; synthetic fixture observations are not authenticated provider receipts or deployment evidence. All journal views carry `runtimeAdmission: HOLD`.

The explicit schema initializer creates schema3 only from recorded paused/drained schema1. Before any journal-mode or constructor DDL write, the constructor refuses schema2 and an old marker coexisting with extension objects. Schema3 validation requires exactly thirteen named tables, fifteen named triggers and the twenty normalized extension table/trigger definitions. It does not validate all base-table DDL, views or indexes. FactoryControl readers register correct-arity default-deny claim insertion/start functions plus the pure witness comparator and skip old constructor DDL. The journal alone installs its module-private gate, closed by default and shared across instances on the controller. Immutable triggers protect manifest/slots/binding/abort/claim rows and effect identity. SQL and JS require matching claim witnesses before parent success and refuse incomplete or corrupted plans. Multiquery observation can transiently fail closed during another connection's atomic claim; no snapshot-availability guarantee is asserted.

These are guards for cooperating host code with the reviewed immutable schema. The public writable database handle permits an arbitrary holder to replace UDFs or alter/drop triggers; this proposal does not confine that authority. A pre-migration SQL connection fixture tests known DML refusals. Old writers can still reset the schema marker using PRAGMA or alter/drop triggers through unrestricted DDL; mixed-state refusal does not prove quiescence of old native writers, already admitted dispatches, arbitrary SQL authority holders or remote workers. The live schema1 database and prior frozen schema2 prototype remain untouched.

Both `claimNativeMission()` and `runNativeMission()` refuse flagged source-only tasks before worker preparation or paid reservation/start. The lower controller sender also refuses. Parent observation checks expected children before writing completion output, and an already-succeeded parent is checked before its early return. NativeCell reports child/manifest blockers and HOLD before sending any child to the Flow observer.

The v2 pure contract is a distinct successor copied into this checkout. It changes the old optional `taskType: development` shape to mandatory `taskType: software`, requires a codex branch and the complete original classification/manifest specification, and authenticates the fixed plan. The original pure v1 checkout, failed first test evidence and corrected 32-case retained proof are preserved unchanged. The successor's envelope limit is 262,144 bytes; body/proof/depth/node limits remain the inherited restricted prototype limits.
